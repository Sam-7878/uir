# Predeclared endpoints and controls

Representation comparison: 144 new constructed development requests, 24 recorded
source families, two languages and three input modes. Primary endpoint is the
joint normative state/exact accepted claim set. Both conditions have the same
parser, information, actions, policies, support guard and renderer. Family
bootstrap retains language/mode rows and uses seed 20261012 / 10000 samples;
the sole primary comparison is shared-UIR minus equivalent-specialized.

Output comparison is separate: previously observed 272 oracle-like authorized
catalogs. Renderer v1 compares seven-field native syntax and generic fact-ID
binding, plus deterministic and partial-off controls. Development v2 explicitly
strengthens reference enum/transport binding. Source/packets/models/options are
frozen separately before each run. All previous versions remain negative findings,
not silently replaced estimates. Missing/incomplete is distinct from a semantic
unsupported value even when both make the all-case primary complete endpoint fail.

No verified document/company/template-family-disjoint confirmatory pool has been
established. Available unused FinQA indices are audited, not selected or executed
as a supposedly independent holdout. Claim scope is engineering conformance and
development diagnostics, not broad generalization.
