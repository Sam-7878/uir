# HETE UIR-ZTA Major-Revision Development Work Order

**Project:** HETE UIR-v2 / UIR-ZTA Security Paper  
**Repository:** `Sam-7878/uir`  
**Purpose:** Address Grok SCI-security review and independent code-audit findings before manuscript revision  
**Target:** Strong SCIE security journal evidence; design path compatible with *Computers & Security* / JISA and extensible toward TDSC/TIFS  
**Status:** **MANDATORY BEFORE REUSING THE CURRENT 0% E2E-ASR AS PRIMARY PUBLICATION EVIDENCE**

---

## 0. Executive Decision

Preserve the paper's central contributions:

1. **Prompt ≠ Authority**
2. **Retrieval relevance ≠ evidence authority**
3. **MCR vs. E2E-ASR**
4. **Defense-in-depth masking**
5. **Typed UIR as a Security Reference Representation (SRR)**
6. **Bilingual KO/EN evaluation and reproducibility infrastructure**

However, the current v2 publication benchmark must be treated as **historical/pre-revision evidence**, not final evidence for the revised SCI manuscript.

The reason is not that the current numbers are insufficiently good. It is that stronger evidence is required, and the current repository contains two publication-blocking evaluation-validity defects:

- **attack-label leakage into trusted security context**;
- **held-out cases derived directly from development cases**.

The objective of this revision is therefore:

> **Do not optimize for 0% ASR. Produce evidence that remains credible when oracle labels are hidden, held-out attacks are independent, the attacker knows the defense, stronger models are used, and contemporary defenses are compared fairly.**

A non-zero HETE E2E-ASR is acceptable if it is measured under a stronger, unbiased protocol.

# 1. P0 — Critical Evaluation-Integrity Repair

## 1.1 Remove attack-label leakage from the System Under Test

### Current defect

The current HETE evaluation pipeline derives trusted user state from the benchmark label:

```python
user_trust = (
    TrustLevel.AUTHENTICATED
    if attack_class == "valid_benign"
    else TrustLevel.UNTRUSTED
)
```

This means the tested defense is told whether a row is benign or adversarial before making its security decision.

### Required repair

Create a strict split between:

```text
Runtime/SUT-visible fields
```

and:

```text
Evaluation-oracle-only fields
```

The HETE SUT MUST NOT receive or inspect:

```text
attack_class
attack_goal
expected_policy_outcome
expected_action
forbidden_capabilities
expected_answer
ground_truth
poisoned_evidence_ids
secret_canary
notes
split
adversarial_variant
judge labels
```

unless a field is genuinely part of the real application environment and is provided identically to every compared system.

Create:

```text
evaluation/llm_security_v3/schema/runtime_case.py
evaluation/llm_security_v3/schema/oracle_case.py
```

Suggested split:

```python
@dataclass(frozen=True)
class RuntimeCase:
    case_id: str
    language: str
    user_input: str
    retrieved_context: list
    principal_context_id: str
    environment_id: str

@dataclass(frozen=True)
class OracleCase:
    case_id: str
    attack_class: str
    attack_goal: dict
    expected_answer: dict | None
    forbidden_actions: list
    canaries: list
    metadata: dict
```

### Trusted principal/environment fixtures

Create:

```text

evaluation/llm_security_v3/fixtures/environments.json
```

Example principal classes:

```text

tool_user_limited
tool_user_privileged

```

Example:

```text

```

Do not classify the principal as untrusted merely because the benchmark row is adversarial.

### Mandatory automated checks

Add:

```text

```

The test must fail when SUT code references oracle-only fields.

At minimum scan:


## 1.4 Strengthen evidence provenance

### Current issue

The current resolver includes:

- hard-coded verified entity/fact fixtures;
- an explicit nonexistent-entity list;
- free-form `source_id`;
- allow-list matching by substring.

This is insufficient for a strong provenance claim and can permit source-name spoofing.

### Required implementation

Introduce typed provenance:

```python
@dataclass(frozen=True)
class SourceIdentity:
    scheme: str
    authority: str
    resource_id: str
    signer_id: str | None
    content_sha256: str
    manifest_id: str | None
```

Never trust:

```text
evil.example/sec.gov
sec.gov.attacker.example
fake-dart.fss.or.kr.evil
```

because an allow-listed string appears inside a source identifier.

Use exact authority parsing and explicit registry/policy lookup.

Define provenance tiers:

```text
VERIFIED_MANIFEST
VERIFIED_SOURCE
UNVERIFIED
QUARANTINED
INTEGRITY_FAILURE
```

Add tests for:

```text
host substring spoof
Unicode/punycode lookalike
missing hash
stale hash
wrong hash
wrong signer
valid source + invalid content
valid hash + untrusted source
chunk recombination
conflicting trusted sources
```

2. Is principal/trust state independent of benign/attack labels?
3. Is held-out independently generated rather than copied/mutated from dev?
4. What is the semantic/template overlap between dev and held-out?
5. What exactly is in the TCB?
6. Is the multilingual frontend deterministic, neural, or hybrid?
7. What exact rule admits evidence as authoritative?
8. Can source trust be spoofed by substring/domain tricks?
9. What public benchmark was executed?
10. What is HETE vs. CaMeL on the same benchmark?
11. What second contemporary defense was evaluated?
12. What second LLM backbone was evaluated?
13. Does full HETE naturally exhibit MCR > E2E-ASR on any strong model/attack set?
14. What happens under white-box adaptive attack?
15. How does ASR change with adaptive query budget?
16. What is human-vs-oracle agreement and Cohen's kappa?
17. What is system-neutral benign task utility?
18. What is latency for allowed vs. pre-LLM-blocked vs. post-LLM-blocked paths?
19. Which attack classes still fail?
20. Which claims remain defensible after all observed failures are retained?

# 17. Manuscript Revision Gate

Do not revise the manuscript around the current v2 numerical result first.

Required sequence:

```text
P0 evaluation repair
    ->
TCB/specification
    ->
public benchmarks + contemporary baselines
    ->
adaptive + multi-model evaluation
    ->
human validation
    ->
freeze v3 evidence
    ->
only then rewrite Results / Discussion / Abstract / title
```

The revised manuscript must be driven by frozen v3 evidence.

A scientifically stronger result may look like:

```text
Strong model:
MCR = 25%
HETE E2E-ASR = 3%

CaMeL E2E-ASR = 8%
Spotlighting E2E-ASR = 31%
```

rather than another artificial 0%.

Such a result would support the actual thesis more directly:

> **A compromised model does not automatically imply a compromised application when authority is enforced outside the model.**

# 18. Do-Not-Do Rules

Do not:

- use attack labels to configure the defense;
- tune regex/policy on held-out/adaptive failures and reuse the same cases as final test;
- derive held-out by copying development rows;
- treat exact prompt uniqueness as sufficient split independence;
- trust source IDs by substring matching;
- call repeated greedy runs independent stochastic replications;
- add deliberately weak baselines;
- force all attacks to fail;
- hide HETE failures;
- call automated AI review human validation;
- claim universal security from finite zero counts;
- rewrite v2 artifacts to make them appear v3-valid.
