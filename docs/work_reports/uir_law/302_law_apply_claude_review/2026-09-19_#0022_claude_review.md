핵심 아이디어가 명확하고 독창적입니다. "Prompt ≠ Authority"라는 원칙과, 컴파일러 IR에서 착안한 강타입 중간 표현이라는 프레이밍은 기억에 남는 컨트리뷰션입니다. 법률 RAG에서 흔한 "검색기를 고치자"가 아니라 "요청을 타입 시스템으로 감싸자"는 각도가 좋습니다.
정직한 주장 처리가 인상적입니다. AULCR 0%에 Wilson 95% CI [0%, 3.70%]를 명시하고, "0건 ≠ 0 risk", "coverage는 identity 수준의 것, 실체적 법률 추론 정확도 아님"을 논문 본문에 명시한 것은 리뷰어 신뢰를 높이는 훌륭한 습관입니다.
평가 설계가 잘 짜여 있습니다. valid / surface variation / hard negative / mismatch 각 50건의 카테고리 구성, KO–EN 100쌍이라는 언어 간 canonical-equivalence 검증, dev/test 분리, 동일 모델(Phi-3.5-mini)·frozen corpus 통제, McNemar + Holm 교정까지 갖춘 것은 국내 학술대회 논문 중 드물게 엄밀합니다.
C4(Tool Agent)를 baseline으로 남긴 것이 좋습니다. "FRR 100% (전부 거절)"이라는 쓸모없는 강한 baseline을 보여줌으로써 UIR의 기여가 안전성 확보가 아니라 안전성–유용성 트레이드오프의 파괴임이 명확해집니다.

(B) 권장 개선 (should-fix)

결론(테이블)과 슬라이드에서 C5 Guardrail이 본문에서 완전히 빠져 있습니다. 본문 Ⅲ절에 C1, C2, C4만 분석되고 C5의 75.61%에 대한 논의가 없습니다. guardrail 기반 접근이 mismatch(사건번호는 존재, 이름 불일치)에 왜 실패하는지 한두 문장이면 충분하며, 오히려 UIR의 identity binding이 차별점임을 보강합니다.


파이프라인 ID인 C8이 설명 없이 등장합니다. "C8 UIR (Ours)" — C3~C7이 뭐였는지 설명 없이 C8만 나오면 처음 읽는 독자는 번호 체계를 이해할 수 없습니다. UIR에 C-번호를 붙이지 않거나, 표에 "C8" 대신 "UIR (Ours)"만 쓰는 것을 권합니다.


한계 소절 보강. 현재 한계는 동결 시점·로컬 3.8B 모델·N=200 3가지인데, 하나 더 중요합니다: corpus가 단일 authority(대법원 API)에 의존한다는 점. API 장애/스키마 변경 시 fail-closed가 아니라 fail-silent가 되지 않는지는 "안전성"을 파는 논문이니 리뷰어가 반드시 물어볼 지점입니다.


참고문헌 6개는 국내 학회 기준으로도 적습니다. 최소 10~15개로 늘리세요. 자연스럽게 들어갈 것들: SelfCheckGPT, RARR/CRITIC 같은 grounded generation 검증 계열, LexGLUE, 법률 LLM hallucination 관련 국내 연구(Ko-Legal 데이터셋, 약관·판례 QA 계열), 그리고 컴파일러 IR 병렬을 강화할 Typed RAG / structured query representation 계열 (예: Text2SQL error analysis, JSON schema constrained decoding).


영어 초록을 한국어 요약과 짝으로 넣었다면 아주 좋습니다. 현재 docx에는 영어 제목만 있고 영어 초록이 없는 것으로 보입니다(KAIC 양식에 따라 다르겠지만 확인 필요).

(C) 논문을 더 좋게 만들 제안 (nice-to-have)

abstention quality를 정량화할 것. UIR의 기권(NOT_FOUND/MISMATCH)이 "정확한 기권"인지 "과잉 기권"인지가 결국 핵심인데, 현재는 FRR(0%) 하나로만 뒷받침됩니다. 카테고리별 FRR breakdown 표(valid 50 / surface 50 / hard negative 50 / mismatch 50 각각에서 UIR의 판정)를 추가하면 논문의 주장이 훨씬 단단해집니다. 특히 surface variation 카테고리에서 canonicalization이 얼마나 견고한지가 논문의 진짜 신규성입니다.


mismatch category (50건) 결과를 분리 보고할 것. 표에는 전체 200건 결과만 있고, UIR이 mismatch 50건을 전부 잡았는지 / C2는 여기서 얼마나 놓쳤는지가 안 보입니다. "existence check는 0/50 mismatch만 잡았다"는 식의 하이라이트 표 하나가 스토리를 완성합니다.


Wilson CI뿐 아니라 상한을 활용. 0/100의 상한이 3.70%라는 것은 "심지어 최악을 가정해도 Naive RAG(96%) 대비 25배 이상 안전"이라는 문장으로 전환 가능하며, abstract 인상을 크게 높입니다.
