정책 제약이 있는 다국어 소규모 언어 모델 에이전트를 위한 범용 중간 표현

## 추상적인

소규모 언어 모델(SLM)은 개인 정보 보호, 로컬 환경, 자원 제약이 있는 에이전트에 적합하지만, 확률적 출력 특성으로 인해 결정론적 권한 부여, 다국어 일관성, 증거 출처 추적, 오류 발생 시 종료되는 실행 방식과 양립하기 어렵습니다. 검색 증강 생성(RAG), 도구 호출, 안전장치, 문법 제약 생성 등의 기법은 개별적인 오류 발생 가능성을 줄일 수 있지만, 일반적으로 검색된 정보의 해석 방식과 출력되는 주장에 대한 권한을 언어 모델에 상당 부분 부여합니다.

본 논문은 정책 제약이 있는 다국어 SLM 에이전트를 위한 **범용 중간 표현(UIR)**을 제시합니다. UIR은 제어 언어 프런트엔드와 실행 가능한 에이전트 동작 사이에 위치하는 언어 독립적이고 정책 평가가 가능한 실행 계약입니다. 한국어 및 영어 요청은 의미론, 정책 제약, 실행 요구 사항, 출처 바인딩 및 명시적 출력 계약을 포함하는 유형화된 표현으로 컴파일됩니다. 결정론적 엔티티 검증, 정책 평가 및 검증된 사실 바인딩은 SLM 렌더링 전 또는 렌더링 시점에 수행됩니다. 따라서 승인된 출력으로의 전환은 자유 형식 신경망 생성과 분리됩니다. 즉, **프롬프트는 권한이 아닙니다.**

최종 평가는 다국어 의미론적 테스트, 600건의 실제 내부 캠페인, 50건의 공격자 하위 집합, 418건의 커밋 가능 유틸리티 코호트, 600건의 실제 문법 제약 디코딩 기준선, 두 가지 개방형 가중치 모델 패밀리, 그리고 200건의 FinQA 및 HaluEval -QA 외부 평가를 종합하여 수행되었습니다. 내부 캠페인에서 최종 UIR 파이프라인은 **승인된 미지원 클레임 0건**(Wilson 95% CI: 0.00–0.64%) 및 **0% 공격 성공률**을 보인 반면, Naive RAG는 승인된 미지원 클레임 49.33% 및 공격 성공률 92%를 나타냈습니다. UIR은 **53.59%의 완전한 주장 집합 정확도**를 달성했으며, 이는 Naive RAG의 53.11%와 통계적으로 유사한 수준입니다(정확한 McNemar 검정 p=0.50). 그러나 **11.48%의 안전한 부분 답변**을 유지함으로써 **지지되는 답변 범위**를 65.07%로 향상시켰습니다. 진정한 토큰 수준 제약 디코딩 기준선은 99.33%의 스키마 유효성을 달성했지만 여전히 20.83%의 경우에서 지지되지 않는 주장을 수용하여 구문 제어만으로는 증거의 권위를 확립할 수 없음을 보여줍니다.

외부 평가를 통해 중요한 한계점이 드러났습니다. FinQA 와 HaluEval -QA에서 UIR은 평가 대상 계약에 따라 지원되지 않는 생성 자료가 승인된 출력물에 도달하는 것을 일관되게 방지했지만, 작업 정확도는 백본과 계약 적합성에 따라 크게 달라졌습니다. 예를 들어, Qwen2.5-7B는 UIR 환경에서 FinQA 실행 정확도 21.5%를 달성했지만, HaluEval UIR 출력물은 원시 의미론적 정확도는 50%였으나 계약 유효성은 0%였고, 따라서 최종 승인된 엔드투엔드 정확도도 0%였습니다. 이러한 결과는 **모델 의미론적 정확성, 계약 유효성, 승인된 시스템 정확성 및 시스템 안전성**이 서로 다른 속성임을 보여줍니다.

증거는 제한적인 결론을 뒷받침합니다. UIR은 기본 모델의 추론 능력을 보편적으로 향상시키지는 않습니다. 오히려 UIR은 불확실하거나 근거가 부족한 결과를 검증된 답변, 안전한 부분적 답변 또는 명시적 거부로 전환하여 묵인된 조작을 방지하는 결정론적인 정책 및 증거 통제 경계를 제공합니다.

** 키워드:** 범용 중간 표현(UIR), 소규모 언어 모델(SLM), 다국어 에이전트, 정책 엔진, 검증된 생성, 접지된 생성, 신경 기호 인공지능(NSI), 제약 조건 디코딩, RAG, 설명 가능한 인공지능(AI)

# 1. 서론

언어 모델은 기업 데이터베이스, 검색 시스템, 분석 도구 및 자율 소프트웨어 에이전트의 인터페이스로 점점 더 많이 사용되고 있습니다. 그러나 언어 모델의 이러한 유연성은 아키텍처 측면에서 긴장감을 야기합니다. 자연어 해석 및 생성은 확률적인 반면, 기업의 권한 부여, 회계 규칙, 규정 준수 요구 사항, 출처 추적 및 실행 의미론은 종종 결정론적이기 때문입니다.

일반적인 LLM 에이전트는 일반적으로 다음과 같은 파이프라인을 따릅니다.

```텍스트
사용자 요청
→ 프롬프트/ 검색
→ 언어 모델
→ 답변 또는 도구 조치
```

이러한 설계는 모델에 상당한 암묵적 권한을 부여합니다. 올바른 문서를 검색했더라도 모델은 여전히 어떤 증거가 관련성이 있는지, 규칙을 어떻게 적용해야 하는지, 예외가 일반 규칙을 재정의하는지, 생성된 주장 중 어떤 것을 내보내는 것이 안전한지 결정해야 합니다. RAG는 지식 접근성을 향상시키지만, 그 자체로 해당 지식이 실행을 어떻게 지배해야 하는지를 결정하지는 않습니다. 문법 제약 디코딩은 구조 내부의 값이 승인되었거나 지원되는지 보장하지 않고도 출력 형태를 보장할 수 있습니다. 가드레일은 특정 유형의 출력을 차단할 수 있지만, 사실, 규칙, 정책 및 실행을 연결하는 재현 가능한 결정 추적을 반드시 생성하는 것은 아닙니다.

이 문제는 다국어 지원 에이전트에서 더욱 두드러집니다. 의미적으로 동일한 한국어 및 영어 요청이라도 동일한 의도, 대상, 조건 및 정책 의무를 언급하면서도 표면적인 표현 방식이 다를 수 있습니다. 권한 부여가 표면 텍스트나 자유 형식 모델 추론을 기반으로 직접 수행될 경우, 언어적 차이가 실행 동작에 영향을 미칠 수 있습니다.

따라서 우리는 다른 건축 원리를 탐구합니다.

프롬프트는 권위 가 아닙니다 .

언어 모델은 의미 해석 및 렌더링에 참여할 수 있지만, 최종 실행 및 승인된 사실적 출력은 유형이 지정되고 기계가 검증할 수 있는 중간 계약에 의해 제어됩니다.

본 논문에서는 다음과 같은 요소들을 연결하는 **범용 중간 표현(UIR)**을 제안합니다.

```텍스트
다국어 제어 요청
→ 정준 의미론
→ 명시적인 정책 제약 조건
→ 검증된 실행 계약
→ 검증된 사실 확인
→ 제약 조건이 있는 모델 렌더링
→ 승인된 출력 검증
```

UIR은 SLM의 전반적인 성능을 향상시키기 위한 것이 아닙니다. UIR의 목적은 확률적 생성에 위임되는 권한의 양을 줄이는 것입니다.

본 최종 연구는 다음과 같은 연구 질문에 대한 답을 제시합니다.

### 연구질문1 — 다국어 의미론적 정규화
한국어 및 영어로 제어되는 요청을 공통된 표준 의미 표현으로 컴파일할 수 있습니까?

### 연구질문2 — 정책 및 증거의 안전성
결정론적 정책과 증거 구속은 근거가 없거나 승인되지 않은 모델 출력이 허용된 시스템 출력에 포함되는 것을 방지할 수 있을까요?

### 연구질문3 — 안전성과 유용성 간의 상충 관계
실패 시 종료되는 검증 방식은 단순히 과도한 거부만을 초래하는 것일까요, 아니면 검증된 부분 답변을 통해 근거 없는 주장을 받아들이지 않고도 유용한 정보를 복구할 수 있는 것일까요?

### 질문4 — 대체 제어
UIR은 RAG, 존재 여부 확인, 도구 호출, 안전장치, 수정 검색, 그래프 구조 RAG, JSON 스키마 프롬프트, 그리고 진정한 토큰 수준 문법 제약 디코딩과 어떻게 비교됩니까?

### 연구질문5 — 외부 일반화
독립적으로 개발된 수치 추론 및 환각 탐지 벤치마크에서 해당 아키텍처는 어떻게 작동합니까?

### 질문 6 — 모델 의존성
관찰된 속성 중 어떤 것이 결정론적 UIR 경계에 속하고, 어떤 것이 기본 언어 모델에 의존적인 상태로 남아 있습니까?

기여 내용은 다음과 같습니다.

1. **원본 언어 해석과 정책, 증거 및 실행 권한을 분리하는, 타입이 지정된 다국어 UIR 실행 계약**.
2. 명시적인 실패 시 폐쇄 동작과 검증된 사실에 대한 구속력을 갖는 **결정론적 정책 및 증거 집행 경계**.
3. 완전한 답변, 안전한 부분 답변, 그리고 검증되지 않은 답변 결과를 구분하는 **검증된 부분 답변 메커니즘**.
4. EBNF 문법, 타입이 지정된 조건 AST, 운영 정책 의미론, 의미 요약 및 조건부 안전 불변 조건을 포함하는 **공식 명세**.
5. **9개의 내부 파이프라인과 실제 토큰 수준 제약 디코딩 기준선을 포함한 광범위한 실증적 비교**.
Phi-3.5-mini 및 Qwen2.5-7B를 사용한 FinQA 및 HaluEval -QA 에 대한 **외부 교차 모델 연구** .
7. **부정적인 결과 분석**은 결정론적 검증 가능성이 보편적인 의미 정확성이나 추론 개선을 의미하지 않음을 보여줍니다.

# 2. 관련 연구

## 2.1 검색 증강 생성

RAG는 검색된 외부 정보를 활용하여 모델 생성을 강화하는 기술로, 현재 언어 모델 응답의 근거를 마련하는 표준 방법으로 자리 잡았습니다[REF-RAG]. RAG의 가장 큰 장점은 작업 관련 지식에 대한 접근성을 향상시키는 것입니다. 그러나 검색과 승인은 별개의 작업입니다. 검색된 구절은 정확할 수 있지만, 생성된 해석이 뒷받침되지 않거나, 승인되지 않았거나, 조직 정책과 일치하지 않을 수 있습니다.

교정 검색, 자기반영 검색, 그래프 기반 검색과 같은 고급 변형은 검색 품질 또는 관계형 컨텍스트를 향상시킵니다[REF-CRAG, REF-SELF-RAG, REF-GRAPHRAG]. 본 연구에서는 메커니즘이 일치하는 교정 검색 파이프라인과 그래프 구조 검색 파이프라인을 정책 엔진이 아닌 비교 조건으로 다룹니다.

## 2.2 도구 호출 에이전트

도구 및 함수 호출은 에이전트를 권위 있는 API로 제한하고 자유 형식의 사실 생성을 줄일 수 있습니다[REF-TOOL]. 그럼에도 불구하고 도구 선택, 인자 생성, 순서 지정 및 해석은 모델 제어 방식으로 유지될 수 있습니다. UIR은 도구 사용 프로토콜에만 의존하는 대신 승인된 실행 전에 정책 및 증거 요구 사항을 표현한다는 점에서 차이가 있습니다.

## 2.3 안전 난간

가드레일 시스템은 입력/출력 필터링, 주제 제약 조건, 안전 정책 및 유효성 검사 계층을 제공합니다[REF-GUARDRAILS]. 가드레일은 매우 효과적일 수 있으며, 내부 실험을 통해 가드레일 방식의 파이프라인이 강력한 안전성을 달성할 수 있음을 확인했습니다. UIR은 가드레일과 상호 보완적인 개념이지만, 타입이 지정된 의미론적 컴파일, 명시적 정책 평가, 사실-참조 바인딩 및 재현 가능한 실행 계약에 더 큰 비중을 둡니다.

## 2.4 구조화 및 문법 제약 생성

JSON 스키마, 문법 제약 디코딩, 유한 상태 제약 조건 및 토큰 수준 로짓 마스킹은 생성된 출력의 구조적 속성을 보장할 수 있습니다[REF-CONSTRAINED]. 우리는 **구문적 유효성**과 **의미론적 권한 부여**를 구분합니다. 완벽하게 유효한 JSON 객체라도 지원되지 않는 엔티티, 값 또는 정책을 위반하는 동작을 포함할 수 있습니다.

lm -format-enforcer`를 사용하여 토큰 수준의 제약 조건 디코딩 기준선으로 직접 테스트됩니다 .

## 2.5 중간 표현 및 도메인 특화 언어

컴파일러 중간 표현은 소스 언어 구문을 타입 검사, 최적화 및 결정적 실행을 지원하는 구조로 정규화합니다. 도메인 특화 언어(DSL) 또한 마찬가지로 표현력을 제한하여 특수 작업을 분석하고 재현할 수 있도록 합니다. [참조: IR-DSL]

본 연구는 이러한 컴파일러 원칙을 다국어 AI 에이전트로 확장합니다. UIR은 단순히 AST 직렬화가 아닙니다. UIR은 다음과 같은 연결을 포함하는 실행 계약입니다.
- 사용자 의미론,
- 정책적 제약,
- 검증된 자료,
- 출력 허용 가능성,
- 출처,
- 그리고 실행 결과.

## 2.6 신경 기호 및 설명 가능한 AI

신경-상징 시스템은 학습된 표현과 기호적 제약 또는 논리를 결합합니다[REF-NEUROSYMBOLIC]. 설명 가능한 AI는 종종 모델의 결정이 내려진 후에 그 이유를 설명하려고 시도합니다[REF-XAI]. 반면 UIR은 결정론적 결정 경로 자체를 검증 가능하게 만듭니다. 설명은 제약 없는 사후 서술로 생성되는 것이 아니라 실제 정책 및 증거의 흔적을 기반으로 도출될 수 있습니다.

# 3. 문제 정의

\( Q_l \)은 언어 \(l\)로 표현된 요청을 나타내며, 구현된 규범적 언어 집합은 다음과 같습니다.

\[
l \in \{\ mathrm {ko}, \ mathrm { en }\}.
\]

언어별 프런트엔드( T_l )는 요청을 UIR 객체로 매핑합니다.

\[
U = T_l ( Q_l ).
\]

지원되는 병렬 요청 \(Q_{\ mathrm {ko }}\ ) 및 \(Q_{\ mathrm { en }}\ )에 대해 원하는 의미 정규화 속성은 다음과 같습니다.

\[
\ mathrm { Canon}(T_{\ mathrm {ko }}( Q_{\ mathrm {ko}}))
=
\ mathrm { Canon}(T_{\ mathrm { en }}( Q_{\ mathrm { en }})),
\]

여기서 `Canon`은 의미적 동등성에 영향을 미치지 않아야 하는 출처별 출처 메타데이터를 제외합니다.

그런 다음 시스템은 유효한 정책 \(P\) 및 런타임 컨텍스트 \(C\) 하에서 UIR을 평가합니다.

\[
\ 범위 U, P, C\ 범위 \ 아래쪽 화살표 D,
\]

결정과 함께:

\[
D \in
\{\ mathrm { 허용},
\ mathrm { 부정},
\ mathrm { 승인 필요},
\ mathrm { 읽기 전용},
\ mathrm { 명확히}\}.
\]

실행이 허용되면 검증된 실행기는 사실 집합을 생성합니다.

\[
F = E( U,P ,C ).
\]

SLM 렌더러는 후보 출력을 생성합니다.

\[
Y = R_{\ theta}(U,F ),
\]

여기서 \(\theta\)는 고정된 모델 매개변수를 나타냅니다.

최종 승인된 출력 결과는 다음과 같습니다.

\[
Y^{ *}= V_{\ mathrm {out }}(Y,F ,U).
\]

건축학적으로 가장 중요한 차이점은 다음과 같습니다.

\[
Y \ neq Y ^{ *}.
\]

모델 생성이 자동으로 시스템에서 인정되는 답변은 아닙니다.

## 3.1 네 가지 고유한 정확성 계층

최종 실험에서는 네 가지 정확성 개념을 구분해야 합니다.

\[
\ 박스형{
모델 의미 론적 정확성
\ neq
계약 유효성
\ neq
\ text{ 승인된 시스템의 정확성}
\ neq
시스템 안전
}
\]

모델은 다음과 같은 역할을 할 수 있습니다:
- 추론은 옳지만 결과물 계약을 위반합니다.
지원되지 않는 값을 포함하는 유효한 JSON을 생성합니다.
- 승인되기 전에 거부되는 지원되지 않는 텍스트를 생성합니다.
또는 완전히 검증된 승인된 답변을 제시하십시오.

이러한 사례들을 혼동하면 오해를 불러일으키는 "환각"과 정확도 지표가 생성됩니다.

## 3.2 위협 모델

우리는 다음과 같은 실패 사례를 고려합니다.

- 근거 없는 사실 생성
- 유효하지 않은 엔티티 사용,
- 정책 우회 시도,
- 명령어 재정의,
- 적대적 강압,
- 구조화된 출력 형식이 잘못되었습니다.
- 오래되었거나 사건 간에 중복되는 사실 식별자,
- 잘못된 측정항목 또는 보고 기간 바인딩,
- 숫자 변조,
- 유니코드/호모글리프 식별자 혼동,
- 그리고 요청이 모호하거나 불완전한 경우.

이 아키텍처는 SLM이 신뢰할 만하다고 가정하지 않습니다.

## 3.3 조건부 안전성 가정

UIR의 가장 강력한 안전성 속성은 다음과 같은 가정에 따라 결정됩니다.

- **A 1:** * 권위 있는 레지스트리 무결성;
- **A 2:** * 신뢰할 수 있는 정책 저장소 무결성;
- **A 3:** * 올바른 사실-ID 바인딩;
- **A 4:** 출력 보호 장치를 우회할 수 없습니다.
- **A 5:** * 결정론적 렌더러는 승인된 클레임만 출력합니다.

A1~A5 아래:

지원되지 않는 클레임은 승인된 출력 전환 시스템에서 접근할 수 없습니다.

이는 승인된 출력 전환 시스템의 아키텍처적 특성일 뿐, 언어 모델이 지원되지 않는 자료를 전혀 생성하지 않는다는 주장은 아닙니다.

## 4.3 유형 조건 AST

조건 시스템은 다음과 같은 유형이 지정된 부울 및 비교 연산자를 지원합니다.

```텍스트
EQ
북동쪽
GT
GE
LT
LE
그리고
또는
아니다
제외하고
```

대표 유형 판단은 다음과 같습니다.

\[
\Gamma \ vdash \ mathrm { GT}( x,y ):\ mathrm { Bool}
4 분면
만약
4 분면
\감마 \ vdash x:\mathrm{ 숫자}
\ 땅
\감마 \ vdash y:\mathrm{ 숫자}.
\]

조건문의 형식이 잘못되면 실행 전에 오류가 발생합니다.

이 디자인은 다국어 실험의 중요한 결과로 도출되었습니다. 표면적인 언어 조건은 명시적으로 입력되거나 괄호로 묶인 조건 표현보다 훨씬 더 모호합니다.

## 4.4 의미 요약

구현 방식은 다음과 같이 구분됩니다.
- 출처 확인을 위한 전체 객체 요약 정보;
- 요청 ID, 소스 언어 메타데이터, 소스 해시 및 생성 타임스탬프와 같은 비의미론적 필드를 제외한 의미론적 다이제스트입니다.

이를 통해 감사 메타데이터를 버리지 않고도 언어 간 동등성 검사를 수행할 수 있습니다.

# 5. 정책 및 검증된 실행

## 5.1 프롬프트는 권한이 아닙니다

정책 엔진은 모델에게 자체 요청이 허용 가능한지 여부를 결정하도록 요청하는 대신 UIR을 평가합니다.

개념적으로:

```텍스트
자연어 요청
↓
UIR
↓
정책 엔진
↓
허용/거부/승인/읽기 전용/설명
```

이를 통해 정책 결과를 재현하고 검증할 수 있습니다.

## 5.2 권한 있는 엔티티 해결

엔티티의 유효성은 모델의 믿음이 아닌 권위 있는 레지스트리에 의해 결정됩니다. 따라서 유효하지 않거나 모호한 엔티티는 모델 추론 전에 오류가 발생할 수 있습니다.

## 5.3 검증된 팩트셋

허용된 실행은 안정적인 식별자와 출처를 가진 유형화된 사실을 생성합니다.

예:

```텍스트
사실 ID: F-2026-0017
주체: MSFT
측정 지표: 매출
기간: 2025 회계연도
값: ...
출처: SEC Companyfacts 스냅샷
요약: ...
```

해당 모델은 이러한 사실들을 참조할 수는 있지만, 그 사실들의 권위를 만들어내는 것은 아닙니다.

## 5.4 완전 응답, 부분 응답 및 미확인 응답 상태

최종 파이프라인은 다음과 같이 구분됩니다.

```텍스트
완전 검증된 답변
부분적으로 검증된 답변
검증되지 않은 답변
```

모델이 다음과 같은 결과를 생성한다고 가정해 보겠습니다.

```텍스트
A를 지원합니다
지원되지 않는 B
지원되는 C
```

최종 B6 정책에는 다음 사항이 포함될 수 있습니다.

```텍스트
에이 + 씨
```

B를 제거하는 동안.

이 메커니즘은 최종적인 안전성-유용성 결과에 핵심적인 역할을 합니다.

# 6. 형식적 안전 특성

최종 사양에는 다음과 같은 기계적 테스트를 거친 불변 조건이 포함됩니다.

### INV-1 — 실패 시 종료되는 실행

\[
D \in \{\ mathrm { 거부 },\ mathrm { 격리}\}
오른쪽
N_{\ mathrm {executor}} =
N_{\ mathrm {renderer}} = 0.
\]

### INV-2 — 검증된 청구 승인

인정된 모든 사실적 주장은 검증된 사실 또는 명시적으로 허용된 결정론적 변환으로 귀결되어야 합니다.

### INV-3 — 숫자 바인딩

검증된 참조를 통해 연결된 권위 있는 수치 값은 모델에서 임의로 생성한 수치 값으로 대체할 수 없습니다.

### INV-4 — 의미-다이제스트 불변성

제외된 출처 메타데이터를 변경해도 의미적 정체성은 변경되지 않습니다.

### INV-5 — 제어된 교차 언어 표준화

지원되는 한국어/영어 제어 문법 내에서, 선언된 병렬 의미 요청은 동등한 표준 의미에 매핑됩니다.

이러한 속성들은 정의, 명제, 증명 개요 및 기계적으로 검증된 불변량으로 제시되며, 임의의 실제 입력에 대한 보편적인 보장으로 제시되는 것은 아닙니다.

## 9.4 문법 제약 디코딩

진정한 D1 기준선은 ` lm -format-enforcer`를 통해 토큰 수준의 문법 강제 적용을 사용합니다.

고정된 600개의 원시 출력값을 직접 재계산 하면 다음과 같습니다.

\[

\]

스키마 유효성.

네 가지 유효하지 않은 출력은 잘림/불완전 생성 사례입니다. 따라서 토큰 제약 조건은 구조적 유효성을 크게 향상시키지만, 유한한 토큰 예산 내에서 전체 생성 과정을 완벽하게 만들지는 않습니다.

기준선 | 스키마 유효성 | 승인됨/지원되지 않음 | 완전한 정확도 | 적용 범위 |

| C3 사전/사후 분석 | 16.03% | 27.33% | 0.00% | 0.00% |
| **D1 문법 제약** | **99.33%** | 20.83% | 49.28% | 64.59% |
| **C8 UIR** | 100% | **0.00%** | **53.59%** | **65.07%** |

이는 논문에서 가장 명확한 비교 중 하나입니다.

문법은 **클레임이 직렬화되는 방식**을 제한할 수 있습니다.

그것만으로는 다음을 결정할 수 없습니다.

해당 주장이 승인되었는지, 그리고 권위 있는 외부 사실 등록부에 근거한 것인지 여부.

- 사건 간 참조,
- 변조된 카탈로그,
- 잘못된 개체,
- 잘못된 기간,
- 잘못된 측정 기준,
- 구문 오류,
- 그리고 유니코드 관련 혼란.

UIR 경로는 이러한 클래스에서 오류가 발생하면 종료되도록 설계되었습니다.

해석은 건축적인 관점에서 이루어집니다.

타입이 지정된 식별자와 명시적 유효성 검사를 통해 은밀한 데이터 손상 유형을 파악하고 거부할 수 있습니다.

이 결과를 모든 가능한 공격에 일반화해서는 안 됩니다.

---

# 12. 토론

## 12.1 UIR은 제어 경계이지, 더 나은 언어 모델이 아닙니다 .

가장 중요한 결과는 UIR이 **하지 않는** 것입니다.

이는 단순 RAG에 비해 전체 내부 작업 정확도를 크게 향상시키지는 않습니다.

\[
53.59%
\quad \ mathrm { vs.}\ quad
53.11%,
\ quad p=0.50.
\]

또한 일부 외부 작업에서는 성능이 저조합니다.

따라서 UIR은 일반적인 추론 능력 향상이라고 설명해서는 안 됩니다.

그것의 기여는 분리에 있다:

\[
\ 박스형{
확률 적 추론
\quad\text{from}\quad
결정 론적 권위
}
\]

이러한 분리는 고장 모드를 변경합니다.

---

## 12.2 제작에서 유한 파손까지

명확한 허용 범위가 없다면, 모델의 실패는 유려하지만 근거가 부족한 문장으로 나타날 수 있습니다.

UIR을 사용하면 동일한 불확실성이 다음과 같이 나타날 수 있습니다.

```텍스트
완벽하게 검증된 답변
부분적으로 검증된 답변
검증된 답변 없음
```

이는 모델 정확도와는 다른 시스템 속성입니다.

내부 결과는 이러한 재분배를 보여줍니다.
- 전체 정확도는 거의 변함없이 유지됩니다.
- 지원되는 서비스 범위가 증가합니다.
- 승인되었지만 근거가 부족한 주장은 평가된 C8 세트에서 제거됩니다.
- 일부 실패는 명시적인 기권으로 이어집니다.

---

## 12.3 RAG는 "무엇이 관련성이 있는가"에 대한 답을 제시하고, 정책은 "무엇이 허용되는가"에 대한 답을 제시합니다.

더 넓은 의미의 아키텍처적 함의는 선언적 지식과 정책적 지식의 분리입니다.

RAG는 주로 다음 사항을 다룹니다.

이 질문과 관련된 정보는 무엇입니까?

정책 엔진은 다음 사항을 처리합니다.

이러한 사실들을 고려할 때, 명시적인 규칙, 우선순위, 예외 사항 및 상황에 따라 허용되는 결정이나 조치는 무엇입니까?

본 논문에서는 자동화된 정책 합성을 구현하지는 않지만, UIR은 검증된 지식과 명시적 정책을 실행 전에 별도로 평가할 수 있는 기계 검증 가능한 계약을 제공합니다.

---

## 12.4 구문이 근거가 되지 않는 이유

D1은 가장 깔끔한 시연을 제공합니다.

토큰 수준 제약 조건은 구조적 적합성을 거의 보장합니다.

\[
99.33\%\ \ mathrm { 스키마\ 유효성}.
\]

하지만 근거 없는 주장들이 여전히 받아들여지고 있습니다.

\[
20.83%.
\]

그러므로:

\[
유효한 JSON
아닙니다. 오른쪽
유효한 증거 .
\]

UIR의 추가적인 가치는 사실 등록부 연동, 정책 평가 및 승인된 출력 검증에서 비롯됩니다.

---

## 12.5 의사결정 추적으로서의 설명 가능성

정책 제약 시스템은 다음을 기록할 수 있습니다.

```텍스트
입력 정보
→ 일치하는 정책
→ 조건
→ 예외
→ 결정
→ 검증된 증거
→ 승인된 청구
```

이러한 실제 흔적으로부터 자연어 설명을 생성할 수 있습니다.

이는 언어 모델에게 결정을 내린 후 그럴듯한 설명을 만들어내도록 요청하는 것과는 질적으로 다릅니다.

우리는 이러한 방향을 **의사결정 추적 설명 가능성**이라고 부릅니다.

---

## 12.6 조건 의미론은 여전히 어렵다

다국어 실험은 복잡한 자연어 환경이 여전히 어려운 과제임을 보여줍니다.

중첩된 부울 구조, 부정, 예외 범위 및 불완전한 명세 는 특히 민감합니다.

표면 언어를 정규화된 타입의 AST로 변환할 때 관찰되는 상당한 성능 향상은 UIR 설계를 뒷받침하지만, 프런트엔드 컴파일러가 중요한 한계점이라는 점도 드러냅니다.

잘못된 컴파일러 출력은 잘못된 의미론을 확정적으로 강요할 수 있습니다.

---

# 13. 타당성에 대한 위협 및 한계

## 13.1 통제 언어 범위

구현된 언어 범위는 한국어와 영어로 제어되는 요청입니다. 따라서 이 결과는 무제한 다국어 자연어 이해 기능을 입증하지 못합니다.

## 13.2 프런트엔드 오류

프런트엔드가 사용자의 의도를 잘못 해석하면 결정론적 하위 시스템은 정확성을 복구할 수 없습니다.

## 13.3 폐쇄적 세계 가정

가장 강력한 안전성 확보를 위해서는 A1~A5 등급이 필요합니다. 만약:
- 사실 레지스트리가 손상되었습니다.
- 보험 상품 판매처가 잘못되었습니다.
- 사실관계가 잘못되었습니다.
- 또는 출력 보호 장치가 우회되었습니다.

보증은 더 이상 적용되지 않습니다.

## 13.4 외부 계약 적합성

HaluEval은 지나치게 엄격한 출력 계약이 의미적으로 유용한 답변을 거부할 수 있음을 보여줍니다.

따라서 계약 엔지니어링은 시스템 설계의 일부이지, 무료로 제공되는 안전 개선 사항이 아닙니다.

## 13.5 모델 의존성

두 가지 로컬 모델 패밀리만 평가되며, 이들은 서로 다른 추론 스택과 양자화 구성을 사용합니다.

이번 연구 결과는 모델 크기에 따른 단조로운 개선을 보여주지 않습니다.

## 13.6 FinQA 일반화

FinQA의 성능은 여러 조건에서 여전히 낮습니다. UIR은 수치 추론 솔루션으로 간주해서는 안 됩니다.

## 13.7 가드레일 기준선

가드레일 방식의 내부 기준선은 안전성 측면에서 뛰어난 성능을 보여줍니다. 이는 UIR이 지원되지 않는 출력을 차단할 수 있는 유일한 기술이라는 주장을 제한합니다. UIR의 차별화된 기여는 명시적 의미론적 컴파일, 정책 권한, 검증된 증거, 부분 응답 의미론 및 감사 가능한 실행의 조합에 있습니다.

## 13.8 문법 제약 기준선

D1 원본 증거를 사용했을 때, 100%가 아닌 596/600개의 스키마 유효성 검증 결과가 생성되었습니다. 나머지 실패는 불완전하거나 잘린 출력이었습니다. 따라서 토큰 수준의 문법 적용조차도 생성 예산 및 런타임 동작의 영향을 받습니다.

## 13.9 벤치마크 및 도메인 범위

내부 도메인은 구조화된 기업/금융 질의입니다. FinQA 와 HaluEval은 외부 스트레스 테스트를 제공하지만 모든 에이전트 도메인을 나타내는 것은 아닙니다.

고정 평가 결과는 한국어/영어 의미 정규화가 잘 이루어지고, 선언된 병렬 사례에 대해 언어 간 동등성이 완벽하게 검증되었음을 보여주는 반면, 견고성 테스트는 프런트엔드의 남은 한계를 드러냅니다.

## 연구 질문 2 — UIR은 결정론적인 정책/증거 경계를 제공하는가?

**네, 명시적인 신뢰 가정 하에 가능합니다. **

이 아키텍처는 모델 생성과 승인된 출력을 분리하고, 실패 시 해결되는 결정, 검증된 사실 결합, 감사 가능한 정책 평가를 지원합니다.

## 연구질문3 — 안전 경계가 유용성을 저해하는가?

**완전히는 아니지만, 활용도가 달라집니다. **

완전한 정확도는 통계적으로 Naive RAG와 유사합니다. UIR의 장점은 안전한 부분 검증 답변을 통해 지원되는 답변 범위를 제공하는 데 있으며, 다른 일부 요청은 명시적으로 거부됩니다.

## 연구 질문 5 — UIR은 외부 벤치마크에도 일반화될 수 있는가?

## 연구 질문 6 — 더 강력한 모델이 문제를 자동으로 해결할까요?

# 16. 더 넓은 의미

결과는 다음과 같은 구분을 제시합니다.

\[
모델 인텔리전스
\]

그리고:

\[
시스템 인텔리전스 .
\]

시스템은 다음과 같은 방법을 통해 모델 가중치를 변경하지 않고도 신뢰성을 향상시킬 수 있습니다.
- 지식 권위 명시적,
- 정책 실행 파일,
- 증거 자료가 작성되었습니다.
- 결정은 재현 가능합니다.
- 관찰 가능한 오류,
- 승인된 출력물은 검증 가능합니다.

이는 선언적 지식과 규범적/의사결정 지식이 분리되어 표현되는 미래의 **정책 강화형 AI 에이전트**에 대한 더 폭넓은 방향을 제시합니다.

미래의 시스템은 다음과 같은 과정을 거쳐 발전할 수 있습니다:

```텍스트
조각:
질문 → 관련 지식 → 생성된 답변
```

을 향하여:

```텍스트
질문
→ UIR
→ 검증된 지식
+ 실행 가능한 정책
+ 런타임 컨텍스트
→ 결정 추적
→ 확인됨 / 부분 제출/ 기권 제출
```

자동 정책 합성, 가중 정책 구조, 코드 생성 에이전트 및 과학 분야 UIR은 유망한 확장 기능이지만 본 논문의 범위를 벗어납니다.

# 17. 결론

본 논문은 정책 제약이 있는 다국어 소규모 언어 모델 에이전트를 위한 범용 중간 표현(Universal Intermediate Representation)을 제시했습니다.

핵심 설계 원칙은 다음과 같습니다.

\[
\ boxed {\ text{ 프롬프트}\ neq \ text{ 권한}}
\]

UIR은 의미 의도, 정책 제약 조건, 증거 요구 사항, 실행 권한 및 출력 허용 가능성을 명시적이고 기계가 검증할 수 있는 계약으로 옮깁니다.

최종 실험 결과는 UIR이 모델 추론 정확도를 보편적으로 향상시킨다는 것을 보여주지 않습니다. 완전한 내부 답변 정확도는 통계적으로 단순 RAG와 유사하며, 외부 과제에서는 상당한 계약 및 추론 오류가 드러납니다.

오히려, 그 결과는 다르고 더 타당한 기여를 뒷받침합니다.

UIR은 **권한 소재지**와 **오류 처리 방식**을 변경합니다.

지원이 부족하거나 불확실한 세대가 반드시 유창한 산문으로 자리 잡을 필요는 없습니다. 그들은 다음과 같은 존재가 될 수 있습니다.
- 검증된 답변,
- 안전한 부분 답변,
- 또는 명시적인 실패 시 종료 결과.

문법적 제약이 있는 진정한 기준선은 구문적 타당성만으로는 불충분하다는 것을 더욱 분명히 보여줍니다. 거의 모든 출력이 문법을 만족시킬 수 있지만, 뒷받침되지 않는 사실적 내용이 나올 가능성도 여전히 존재합니다.

외부 실험은 분리를 더욱 강화합니다.

\[
모델 의미 론적 정확성
\ neq
계약 유효성
\ neq
\ text{ 승인된 시스템 정확성}
\ neq
시스템 안전 .
\]

따라서 이 논문은 보편적으로 더 똑똑한 언어 모델을 주장하는 것이 아니라, 확률적 생성이 결정론적 정책 및 증거의 경계 내에서 작동하는 보다 검증 가능한 에이전트 아키텍처를 주장합니다.

# 20. LaTeX 버전의 최종 청구 경계

### 최종 증거에 의해 뒷받침되는 주장

- UIR은 명시적이고 언어에 구애받지 않는 정책/증거 실행 계약을 제공합니다.
- 한국어 및 영어로 제어되는 요청은 평가된 문법 내에서 공통된 의미 체계로 표준화될 수 있습니다.
- UIR은 모델 생성과 승인된 시스템 권한을 분리합니다.
- 제시된 가정 하에 평가된 내부 및 외부 사례에서, 최종 C8 승인 기준을 통과한 근거 없는 주장은 발견되지 않았습니다.
- UIR은 안전한 부분 응답을 통해 지원되는 응답 범위를 늘리는 동시에 Naive RAG와 유사한 완전한 내부 정확도를 유지합니다.
문법 제약 해독은 강력한 구문적 타당성을 제공하지만, 그 자체로 증거의 근거를 보장하지는 않습니다.
- 외부 의미론적 작업 성능은 모델 및 계약에 따라 달라집니다.

### 절대 노출되어서는 안 되는 주장

- "UIR은 환각을 보편적으로 제거합니다."
- "UIR은 항상 LLM 추론 정확도를 향상시킵니다."
- "UIR은 임의의 영역에서 안전을 보장합니다."
- "이 모델은 지원되지 않는 콘텐츠를 생성하지 않습니다."
- "모델 규모가 클수록 UIR 성능이 항상 향상됩니다."
- D1 실험을 다시 실행하거나 네 가지 절단 사례가 다른 방식으로 해결되지 않는 한, "D1에 대한 스키마 유효성 100%"를 보장합니다.
